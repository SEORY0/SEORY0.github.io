# KKACHI 하위 페이지 (작동 원리 · 콘솔 · 보고서 · 연구 노트 · 대기자 명단) 설계

선행 문서: `2026-09-28-kkachi-home-design.md`(홈). 여기에 적지 않은 규칙은 모두 홈 문서를 따른다
(색 토큰 §4, 타일 계약 §5, 금지 규칙 §9, 반응형 §10, 접근성 §11, 자개 §13).

## 1. 목적과 범위
홈의 버튼이 가리키던 다섯 곳을 각각 한 화면짜리 단일 섹션 페이지로 만든다. 디자인 테마는 홈과 같다.
Tenfold처럼 옻칠 검정 면 위에 4×4 타일 격자를 두고, 라인아트를 천천히 움직이며, 실제 자개 텍스처를 쓰고, 버튼을 격자 사이에 끼워 넣는다.
내용은 프로토타입(`kkachi/index.html`)의 해당 섹션에서 가져온다. 사실은 모두 담고, 긴 설명은 한 줄로 줄인다(한 화면 요약형).

| 번호 | 페이지 | URL | 원천 섹션 |
|---|---|---|---|
| 01 | 작동 원리 · Method | `/kkachi/method/` | `#method` + `#principles` |
| 02 | 콘솔 · Console | `/kkachi/console/` | `#console` |
| 03 | 보고서 · Report | `/kkachi/report/` | `#report` |
| 04 | 연구 노트 · Notes | `/kkachi/notes/` | `#notes` |
| 05 | 대기자 명단 · Waitlist | `/kkachi/waitlist/` | `#access` |

- 파일은 `kkachi/<slug>/index.html`이다. front matter 없는 정적 HTML이고, 홈과 같다.
- 홈(`kkachi/home/index.html`)의 버튼 href를 `../method/` `../console/` `../report/` `../notes/` `../waitlist/`로 바꾼다.
- 프로토타입 `/kkachi/`는 손대지 않는다.

## 2. 공유 프레임 (중복 제거)
여섯 페이지가 같은 프레임을 쓰므로 공통 부분을 파일로 뺀다.

- `assets/kkachi/kk.css`에 넣는 것: 홈 `<style>`의 1 tokens, 2 base, 3 stage, 4 grid, 5 자개 상감 캔버스(공통 부분과 ㄲ 로고),
  9 buttons, 10 intro column, 11 motion off. 반응형 규칙과 `prefers-contrast`도 여기에 둔다.
- 페이지에 남기는 것: 홈 전용 타일(온주화 +, 라벨, 추적 기록, 여섯 글자)과 각 페이지 전용 타일의 CSS.
- `assets/kkachi/inlay.js`(ES 모듈): 홈 인라인 모듈 스크립트의 자개 상감 로직을 옮긴다.
  - 옮기는 것: 관찰각 보드, 일시정지·동작 줄이기 대응, 컨텍스트 복구, 후퇴.
  - `.inlay` 캔버스를 찾아 `data-scale`, `data-angle`로 초기화한다. 페이지는 `<script type="module" src="../../assets/kkachi/inlay.js"></script>` 한 줄만 둔다.
  - najeon 경로는 모듈 자신의 위치를 기준으로 푼다(`import.meta.url`).
- 홈을 이 공유 파일로 바꾼 뒤에도 **화소 단위로 같아야 한다.** 여러 크기, 프레임, 호버, 동작 줄이기 상태에서 스크린샷 차분으로 확인한다.

## 3. 페이지 공통 구성
- 옻칠 검정 한 화면이다(min-height 100dvh). 왼쪽에 4×4 격자, 오른쪽(좁은 화면에서는 아래)에 글 열을 둔다. 타일 크기와 간격은 홈과 같다.
- **이동 타일 5개**(격자 안에 끼워 넣는다):
  - ㄲ 자개 상감 로고 타일은 홈으로 가는 링크다(`../home/`, 접근 가능한 이름 "KKACHI 홈").
  - 나머지 넷은 현재 페이지를 뺀 다른 페이지 버튼이다(홈과 같은 번호 01–05, 한글 라벨, 영문 모노, →).
  - 05 대기자 명단은 주 버튼(흰 면) 스타일로 격자 오른쪽 아래 근처에 둔다. 대기자 명단 페이지에서는 01–04가 모두 보조 버튼이다.
  - 현재 페이지 버튼은 넣지 않는다. 현재 위치는 글 열 맨 위에 적는다.
- **내용 타일 11칸**(가로 2칸 또는 2×2로 합칠 수 있다). DOM 순서가 곧 읽는 순서다.
- **글 열**: 위에서부터 다음을 둔다.
  - 모노 eyebrow: `01 — Method / 작동 원리`
  - 보이는 `<h1>`: 프로토타입 섹션의 제목 문장
  - 한 문단 소개
  - 샘플 안내: `PROTOTYPE · 2026` + 샘플 문구
  - '움직임 멈춤' 스위치(홈과 같다)
- 타일은 상자 없이 떠 있다. 버튼만 가는 테두리를 쓴다. 내용 타일 안의 글은 Pretendard와 IBM Plex Mono로 쓰고, 최소 글자 크기와 대비는 홈 기준을 따른다.
- **움직임**: 내용 타일마다 그 내용을 그리는 라인아트 모티프가 천천히 돈다(6–16초, 주기가 서로 겹치지 않게).
  호버하면 한층 살아나며 실제 자개 텍스처가 스친다(홈 §13 방식: 타일별 `<pattern>`, 샘플링 색, `background-clip:text`).
  `prefers-reduced-motion`이나 일시정지 스위치를 켜면 모두 멈추고, 구성이 갖춰진 정지 화면을 보여 준다.
- **상태색**: violet `#96688D`는 '확인·발견' 순간(F-01, Confirmed, `3/3`)에만 쓴다. 기각과 보류는 흐린 잉크로 표시한다.
- **샘플 표시**: 수치와 코드는 모두 설명용 샘플이다. 타일이나 글 열에 SAMPLE / 샘플 데이터 · Illustrative를 붙인다.

### 02 콘솔 `/kkachi/console/`
- h1 "뚜껑을 열면, 판단의 기록이 보입니다."
- 소개: "결과만 보여주지 않습니다. 무엇을 의심했고, 어디까지 따라갔고, 왜 버렸는지. 모든 판단은 호출 경로와 재현 기록에 묶여 남습니다."
- **세션 타일**: Session 7F2A · Target sample-imgcodec 2.4 (가상) · Scope 승인된 로컬 빌드 · Elapsed 4분 12초 · SAMPLE
- **호출 그래프(2×2)**: 프로토타입 그래프의 노드와 가설을 홈의 A 타일 언어(마름모 노드, 가는 간선)로 다시 그린다.
  - 경로 fuzz_entry → decode_image → parse_header → read_chunk → copy_rows → memcpy에서 F-01에 닿는다.
  - 가지 H2·H3는 기각, H4는 보류로 흐리게 표시한다.
  - 추적 펄스가 진입점에서 F-01까지 가고, 도착하면 violet으로 확인된다.
- **F-01 발견**: Verified 3/3 · "copy_rows()의 행 길이 계산에서 정수 오버플로" · CWE-190 → CWE-122 · src/rows.c:207 → 212 · STATUS 사람 검토 대기
- **가설 H1–H4(2칸)**:
  - H1 copy_rows()가 헤더의 width 값을 검증 없이 신뢰한다 — Confirmed(경로 5단계 · 재현 3/3)
  - H2 팔레트 인덱스가 배열 경계를 넘는다 — Rejected(read_palette() 경계 검사 확인 · 01:37)
  - H3 inflate_block() 출력 버퍼가 넘친다 — Rejected(출력 버퍼 크기 고정 · 02:28)
  - H4 validate_len()의 부호 비교가 뒤집혀 있다 — On hold(입력 샘플 부족 · 다음 세션)
- **코드(2칸)**: src/rows.c 207 `u32 stride = h->width * h->bpp; // u32 overflow`, 212 `memcpy(row, s, (size_t)h->width * h->bpp);`
  - 주석: 207 "32비트 곱셈이 넘쳐 4바이트 버퍼만 할당", 212 "64비트로 다시 계산한 길이만큼 복사해 힙 경계를 넘어 씀"
- **재현 3/3**: RUN 1 0.41 s, RUN 2 0.39 s, RUN 3 0.40 s, 모두 rows.c:212 · x86_64 · ASan · 고정 시드 · 매 실행마다 새 VM

## 5. 접근성과 시맨틱
- 페이지마다 보이는 `<h1>`이 하나다. `<title>`은 "KKACHI — 작동 원리"처럼 쓰고, meta description과 og:title / og:description / og:url / canonical을 둔다.
- 격자는 내용과 링크가 섞여 있으므로 `<nav>`로 감싸지 않는다. 링크 이름만 보고도 목적지를 알 수 있어야 한다(ㄲ 타일은 "KKACHI 홈").
- 장식 라인아트는 `aria-hidden`으로 숨긴다. 정보가 담긴 타일(단계, 가설, 보고서 항목, 노트, 폼, 이름 설명)의 글은 스크린리더가 읽을 수 있는 실제 텍스트여야 한다.
- 대비, 포커스, 터치 크기, 글자만 200% 확대, 동작 줄이기, 일시정지 기준은 홈과 같다.

## 6. 검증
- 공유 파일로 옮긴 뒤의 홈은 1440×900, 390×844, 320×640과 t=0/6000, 호버, 동작 줄이기에서 이전 스크린샷과 화소 차분이 0이어야 한다(셰이더 캔버스는 같은 관찰각에서 비교).

- 링크 검사: 모든 페이지의 모든 내부 링크가 실제 파일로 풀린다. 각 페이지는 홈과 나머지 네 페이지로 이어진다.

## 7. 구현 중 결정 (2026-09-30)
- **한 화면**
