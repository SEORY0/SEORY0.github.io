# KKACHI 페이지 수상 품질 기준 (셀프 체크 루브릭)

목표: Awwwards(SOTD 이상), FWA(FWA of the Day), Webby(Honoree 이상) 심사를 통과할 만한 품질.
대상은 `/kkachi/home/`과 `/kkachi/{method,console,report,notes,waitlist}/` 여섯 페이지, 그리고 페이지 사이의 금문 전환이다.
아래 종료 조건을 모두 채울 때까지 "심사 → 개선 계획 → 구현 → 회귀 검증 → 재심사"를 반복한다(안전 상한 4라운드).

## 1. 점수 눈금 (모든 심사 공통, 소수 첫째 자리까지)
| 점수 | 의미 |
|---|---|
| 10 | Site of the Month / Site of the Year 후보 |
| 9 | Site of the Day 확실 + Developer Award |
| 8 | Site of the Day 수준 (목표선) |
| 7 | Honorable Mention |
| 6 | 후보작 수준. 잘 만들었지만 기억에 남지 않음 |
| 5 이하 | 잘 만든 템플릿 수준 |

심사자는 실제 수상작(예: Awwwards SOTD, FWA의 에디토리얼·브랜드 사이트)과 견주어 엄격하게 매기고, 점수마다 근거를 붙인다.

## 2. 심사 항목
- **Awwwards 축(가중치)**: Design 40%, Usability 30%, Creativity 20%, Content 10%.
- **Developer 축**: 시맨틱과 SEO, 애니메이션과 전환의 매끄러움, 접근성, 성능, 반응형, 마크업과 코드 품질.
- **FWA 관점**: 혁신성, 장인정신(craft), 감정적 임팩트("wow"), 브랜드 일관성.
- **Webby 관점**: 콘텐츠, 구조와 탐색, 시각 디자인, 기능, 인터랙티비티, 전체 경험.

## 3. 종료 조건 (모두 만족해야 한다)
1. **심사위원 점수**: 심사위원 네 명의 평균이 Design, Usability, Creativity, Content 각각 **8.0 이상**이다. 가중 총점도 **8.0 이상**이다. 어느 심사위원도 어느 항목에 **7.0 미만**을 주지 않았다.
2. **Developer 점수**: 평균 **8.0 이상**이다.
3. **객관 지표**: 여섯 페이지 모두 다음을 만족한다.
   - Lighthouse 모바일: Performance **90 이상**, Accessibility **100**, Best Practices **95 이상**, SEO **95 이상**. 측정은 `.scratch/award/lh.sh`로 한다.
   - CLS 0.05 미만.
   - axe에서 serious·critical 위반 0.
   - 콘솔 오류 0(일반, 동작 줄이기, WebGL 없음, JS 꺼짐).
   - check.sh 가로 넘침 0, 중복 id 0.
   - 금문 전환 검증 통과: 대각선 순서, 흰 화면 번쩍임 없음, 매끄러운 인계, bfcache·새 탭·동작 줄이기 처리.
4. **회귀 없음**: 내용 충실도(프로토타입 사실 누락 0), 링크, 폼(전송·저장 없음), 브랜드 규칙.

## 4. 바꾸지 않는 것 (사용자 결정)
> 2026-10-02 v4 갱신: `2026-10-02-kkachi-v4-symbol-system-design.md`가 이 절보다 우선한다. 홈은 타일 격자를 지키되 왼쪽 위 2×2 메시지 타일(워드마크·헤드라인·한 줄 정의·CTA), 세션 줄 타일, 글자 아트 다섯 개(k1, k2, A, C, I), 이동 타일 셋으로 바뀌었다. 별도의 ㄲ 타일과 온주화 + 타일은 없어졌고, ㄲ은 워드마크 안의 셰이더 상감(화면의 유일한 셰이더)으로 남는다. violet은 '재현 확인'과 '승인'에만, 자개는 입증된 것에만 쓴다. 아래 '홈' 항목의 여섯 글자 아트와 온주화 +는 이 갱신으로 대체된다. 다음 루프에서 되살리지 않는다.
> 2026-10-02 갱신: 구조, 톤, 글꼴은 `2026-10-02-kkachi-v3-unified-design.md` §0–§1이 우선한다. 페이지는 home·why·notes·waitlist(어두운 톤)와 system·dashboard(noindex)이고, 글꼴은 Wanted Sans + Fragment Mono(코드 전용)이며, AI 티 제거 규칙(§4)을 따른다. 아래 항목 가운데 흰 페이지, 다섯 페이지 구성, 프로토타입 전체 내용에 관한 것은 위 문서로 대체된다.
- **홈**
  - 어두운 한 화면 페이지다. Tenfold식 타일 격자, 글자마다 다른 라인아트 여섯 개, 자개 상감 ㄲ 로고와 띄운 온주화 +, nav 대신 격자 속 버튼을 둔다.
  - 홈의 화소 동일성 잠금은 이 루프에서 풀린다. 다만 개념과 구성은 유지한다.
- **다섯 페이지**: 흰(mist) 바탕의 스크롤 인터랙티브 페이지다. 얇은 고정 상단 바와 끝 타일을 두고, 프로토타입 내용은 전부 싣는다.
- **전환**: 금문 패턴(옻칠 `#292623` 위 `#363333` ㄲ)이 대각선 슬라이드(B안)로 왼쪽 아래에서 오른쪽 위로 번지고, 커튼은 항상 옻칠이다.
- **브랜드 금지 규칙**
  - ㄱ 모듈, +, 로고를 회전하거나 45°로 기울이거나 원형 배지에 넣지 않는다. 로고 path는 수정하지 않는다.
  - 금문 패턴은 전환에만 쓴다.
  - 자개는 옻칠 면 위에만 두고, 자개 색을 손으로 고르지 않는다(najeon 텍스처나 스펙에서만 가져온다).
  - violet은 '확인·발견' 순간에만 쓴다.
- **정직성**: 샘플 데이터 표시를 유지한다. 폼은 아무것도 전송·저장하지 않는다. 사실을 지어내지 않는다.
- **기술**: 정적 HTML이고 빌드 단계가 없다. 외부 CDN 의존을 새로 만들지 않는다. 사이트 안의 글꼴만 쓴다.
