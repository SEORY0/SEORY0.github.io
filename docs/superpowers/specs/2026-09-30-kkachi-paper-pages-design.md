# KKACHI 흰 스크롤 페이지와 금문 전환 설계

`2026-09-30-kkachi-subpages-design.md`(한 화면짜리 어두운 하위 페이지)를 대체한다. 홈은 `2026-09-28-kkachi-home-design.md` 그대로
어두운 한 화면으로 남는다. 여기에 적지 않은 브랜드 규칙은 홈 문서를 따른다(§9 금지 규칙, §13 자개).

## 1. 범위
- **홈** `/kkachi/home/`: 그대로 둔다. 버튼을 누르면 §2의 전환을 거쳐 이동하는 것만 더한다.
- **다섯 페이지**를 흰 바탕의 스크롤 인터랙티브 페이지로 다시 만든다: `/kkachi/method/` `/kkachi/console/` `/kkachi/report/` `/kkachi/notes/` `/kkachi/waitlist/`.
  - 한 화면 제약을 없애고, 프로토타입(`kkachi/index.html`)의 해당 섹션 내용을 **모두** 복원한다. 요약하느라 줄인 문구를 원래대로 되돌린다.
  - 스크롤과 클릭에 반응하는 인터랙션을 더한다.
- **이전 어두운 하위 페이지**는 `.scratch/kkachi-dark-subpages/`에 백업하고 교체한다.
- **공유 파일**
  - `assets/kkachi/kk.css`: 홈 전용으로 남긴다(홈을 화소 단위로 그대로 유지하는 것이 기준).
  - `assets/kkachi/inlay.js`: 모든 페이지가 쓴다(자개 상감).
  - `assets/kkachi/transition.js`: 새로 만든다. 모든 페이지가 쓴다.
  - `assets/kkachi/kk-paper.css`: 새로 만든다. 흰 페이지 전용이다.

## 2. 금문 전환 (홈 §9 금지 규칙의 유일한 예외)
- **패턴**: `kkachi/drafts/c-pattern-tile-dark.svg`와 같다.
  - 옻칠 `#292623` 위에 ㄲ(C′1 마스터 path, 모양 그대로)을 `#363333`으로 깐다.
  - 76×136 단위에 벽돌식 배치이고, 모듈 위치는 (14,10), (−24,78), (52,78)이다.
  - 화면 크기에 맞춰 반복하며, 모듈 크기는 약 38–48px다.
  - 회전·기울임·원형 배지는 쓰지 않는다. 모듈은 **평행이동만** 한다.
- **덮기(떠날 때, 약 0.7초)**
  - 같은 출처의 KKACHI 페이지로 가는 링크를 누르면 시작한다.
  - 전체 화면 고정 오버레이가 옻칠로 채워진다(약 140ms, "빈 배경").
  - 각 ㄲ이 왼쪽 아래 (−d, +d)에서 제자리로 미끄러져 들어오며 나타난다(B안). 지연은 대각선 좌표 x−y에 비례해 왼쪽 아래에서 오른쪽 위로 번진다.
  - 모듈 하나는 약 320ms, 전체 번짐은 약 560ms이고, 이징은 `cubic-bezier(.2,.7,.2,1)`다.
  - 다 덮이면 이동한다.
- **걷기(도착했을 때, 약 0.5초)**
  - 도착 페이지는 첫 페인트부터 옻칠 커튼과 패턴이 덮인 상태로 시작한다. 흰 화면이 번쩍이지 않게 `<head>`의 아주 작은 인라인 스크립트와 CSS로 처리한다.
  - 각 ㄲ은 오른쪽 위(+d, −d)로 빠지며 사라지고, 같은 대각선 순서를 따른다. 이어서 옻칠 커튼이 걷힌다.
- **대상**
  - 적용하는 곳: 홈 버튼, 상단 바, 끝 타일, 본문 안의 KKACHI 내부 링크.
  - 적용하지 않는 곳: 새 탭 클릭(Ctrl/⌘/Shift/가운데 버튼), `target`, 다운로드, 같은 페이지 안의 해시 이동, 외부 링크.
  - 뒤로·앞으로 이동: bfcache로 되돌아온 페이지(`pageshow` persisted)는 커튼을 즉시 없앤다. 멈춘 커튼이 남으면 안 된다.
- **동작 줄이기**(`prefers-reduced-motion: reduce`)에서는 전환 없이 바로 이동한다. 도착 커튼도 쓰지 않는다.
- **안전장치**
  - 도착 신호는 `sessionStorage`에 두고, 짧은 유효시간(약 4초)이 지나면 무시한다.
  - JS가 없거나 실패하면 그냥 링크로 동작한다. 커튼은 절대 화면을 막고 남지 않는다(타임아웃으로 강제 해제).
  - 덮는 동안 대상 페이지를 prefetch한다.
- **접근성**: 오버레이는 `aria-hidden`으로 두고 포커스를 가두지 않는다. 이동 중이라는 사실만 `aria-live`로 조용히 알릴 수 있다(선택).

## 3. 흰 페이지 공통 (`kk-paper.css`)
- **색**
  - 바탕 mist `#F0F0F0`, 글자와 선 옻칠 `#292623`, 보조 글자 smoke `#424041`.
  - 가는 선 `rgba(41,38,35,.14)`, 강한 선 `#292623`.
  - 상태색 violet `#96688D`: '확인·발견' 순간에만 쓴다. 흰 바탕에서 대비 4.4:1이므로 큰 글자나 표지에만 쓴다.
  - 새 색은 만들지 않는다.
- **자개**: 흰 바탕에 바로 깔지 않는다. 옻칠 인셋(어두운 판) 안에서만 쓴다. 예: 상단 바의 ㄲ 칩, 콘솔 패널, 자개 패널.
- **글꼴**: Pretendard('Portfolio Sans')와 IBM Plex Mono. 홈과 같은 모노 라벨, 번호 체계(01–05), 가는 라인아트 언어를 쓴다.
- **상단 바**(고정, 얇게)
  - 왼쪽: ㄲ(홈 `../home/`, 이름 "KKACHI 홈").
  - 오른쪽: `01 작동 원리 · 02 콘솔 · 03 보고서 · 04 연구 노트 · 05 대기자 명단`. 현재 페이지는 `aria-current="page"`로 표시한다.
  - 좁은 화면에서는 번호만 보이거나 가로 스크롤로 보여 준다. 드롭다운 메뉴는 만들지 않는다.
  - 스크롤 진행 표시(가는 선)는 선택이다.
- **페이지 구성**
  - 히어로: eyebrow `0N — English / 한글`, h1, 소개, 큰 라인아트 모티프.
  - 본문 섹션: h2, 프로토타입 문구 전체.
  - 끝 타일: 다음 페이지 큰 타일과 홈 타일. 홈의 타일 버튼 언어를 흰 바탕용으로 쓴다(가는 테두리, 번호, →).
  - 푸터.
- **스크롤 인터랙션**
  - 라인아트는 화면에 들어오면 그려진다(IntersectionObserver, 또는 `animation-timeline: view()`를 `@supports`로 감싸 쓰고 대체 경로를 둔다).
  - 동작 줄이기에서는 이미 그려진 상태로 둔다.
  - 루프 애니메이션은 드물게 쓰고 느리게(6–16초) 돌린다.
- **인터랙션 원칙**
  - 클릭할 수 있는 것은 모두 `<button>`이나 `<a>`다(`aria-expanded` / `aria-pressed` / `aria-controls`). 키보드로 조작할 수 있어야 한다.
  - 정보를 호버에만 숨기지 않는다.
- **반응형과 품질**: 320–1920px. 가로 넘침 없음, 중복 id 없음, 콘솔 오류 없음. 글자만 200% 확대해도 겹치지 않는다. 대비는 AA를 지킨다.

## 4. 페이지별 인터랙션
- **01 작동 원리**
  - 단계 도식이 고정된 채, 오른쪽 다섯 단계 글(읽기, 가설, 추적, 재현, 보고: 설명, 샘플 수치, Gate)을 스크롤하면 현재 단계와 관문이 켜진다(스크롤리텔링).
  - 좁은 화면에서는 단계마다 도식을 인라인으로 넣는다.
  - 관문 규칙("조건을 못 채우면 넘어가지 않음, 그 사실도 기록")을 보여 준다.
  - 원칙 P1–P5를 전문으로 싣는다.
  - 샘플 표시: "단계별 수치는 세션 7F2A의 샘플입니다."
- **02 콘솔**
  - "뚜껑을 열면"에 맞춰 옻칠 패널 안에 콘솔을 넣는다.
  - 세션 머리: 7F2A, target, scope, elapsed, 샘플.
  - 호출 그래프: 가설 H1–H4를 누르면 그래프에서 해당 경로가 강조된다.
  - F-01 발견 카드와 코드: src/rows.c 205–214 전체, 줄 주석 207·212 토글.
  - 재현 3/3: RUN 1–3.
  - 세션 기록: 00:00–06:00 타임라인. 스크러버를 끌면 그 시점의 사건(가설 기각 등)이 표시된다.
  - 자개는 패널 안에서만 쓴다.
- **03 보고서**
  - 문서형 전체 보고서: 표지, 01 요약 ~ 06 검토 원문.
  - '작성 규칙 보기' 토글로 여백에 규칙 01–06을 표시한다.
  - 재현 명령 복사 버튼: 복사 결과를 `aria-live`로 알린다.
  - 수정 diff 보기.
  - 샘플 보고서 표시.
- **04 연구 노트**
  - 노트 N-01–N-03 카드. 그림이 스크롤에 맞춰 재생된다. 준비 중 노트는 링크가 아니다.
  - "노트가 나오면 알림 받기 →"는 대기자 명단으로 가며 전환을 거친다.
- **05 대기자 명단**
  - 폼은 이전과 같다: 필수 이메일, 선택 소속, 검사, `role=alert` / `role=status`. 전송이나 저장은 절대 하지 않는다.
  - 이름 풀이는 까치, 흑칠, 끊음질, 자개, 반가운 소식이다.
  - 자개 패널은 옻칠 인셋 안의 셰이더다(포인터 관찰각, `inlay.js`).

## 5. 검증
- **홈**: 전환 스크립트를 넣은 것 말고는 화소 차이 0이다(기준: `.scratch/kkachi-sub/fnd/pw-base`). 버튼을 눌렀을 때 전환이 재생되는지 확인한다.
- **전환**
  - 프레임 캡처로 확인한다: 덮기가 대각선 순서인지, 도착 첫 페인트가 커튼인지(흰 화면이 번쩍이지 않는지), 걷기가 되는지.
  - 뒤로 가기(bfcache), 새 탭 클릭, 동작 줄이기, JS 없음, 연속 클릭을 확인한다.
- **각 페이지**
  - check.sh를 320·390·768·1024·1280·1440 폭과 동작 줄이기에서 돌린다.
  - 콘솔 오류가 없고, 링크가 모두 풀리고, 인터랙션을 키보드로 조작할 수 있어야 한다.
  - 프로토타입과 내용이 대조되어야 한다(빠진 사실이 없을 것). 폼이 전송하지 않는지도 확인한다.
