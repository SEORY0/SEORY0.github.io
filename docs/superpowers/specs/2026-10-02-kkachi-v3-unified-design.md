# KKACHI v3: 통합 디자인 시스템, 한 페이지 제품 소개, 대시보드 샘플

선행 문서: `2026-09-28-kkachi-home-design.md`(홈, 브랜드 금지 규칙 §9, 자개 §13), `2026-09-30-kkachi-paper-pages-design.md`(금문 전환 §2),
`2026-10-01-kkachi-award-rubric.md`(품질 기준). 이 문서가 충돌하는 부분은 이 문서가 우선한다.
작업 전 상태 백업: `.scratch/pre-v3/`.

## 0. 사용자 결정 (2026-10-02)
- 작동 원리·콘솔·보고서를 **한 페이지**로 합친다. 레퍼런스(openai.com/ko-KR/the-defense-factory, xint.io/ko)처럼 "왜 이 제품이 필요한가"를 핵심만 담는다.
- **로고 글자를 두껍게** 한다. 첨부 이미지(`.scratch/v3/ref-wordmark.png`)처럼 ㄲ 마크 뒤에 아주 굵은 "ACHI"를 둔다. 다른 디자인도 이에 맞춰 통일한다.
- **AI가 만든 티를 없앤다.**
  - `01 — Method / 작동 원리` 같은 eyebrow는 쓰지 않는다.
  - 기존 글꼴(Pretendard + IBM Plex Mono, Xint와 같은 조합)을 **Wanted Sans**로 바꾼다.
  - 라벨에 모노 글꼴을 쓰지 않는다. 모노는 코드와 헥스에만 쓰고, 글꼴은 **Fragment Mono**다.
- 새 페이지는 **어두운 옻칠** 톤이다. 연구 노트와 대기자 명단도 어둡게 바꿔 통일한다.
- 대시보드는 **통합 디자인 시스템 + 샘플 화면**으로 준비한다.
- 품질은 계속 Awwwards, FWA, Webby 수상 수준(루브릭)을 유지한다.

## 2. 브랜드 워드마크
- **구성**: ㄲ 마크(C′1 마스터 path, 모양 그대로) + "ACHI"(Wanted Sans 900 Black). 첨부 이미지처럼 맞춘다.
  - 마크 높이는 대문자 높이와 같고, 위아래 정렬도 같다.
  - 마크와 A 사이 간격은 대문자 높이의 약 0.1이다.
  - ACHI의 자간은 좁게 둔다.
- **파일**: 글자를 윤곽선 path로 바꾼 SVG로 만든다(fontTools). 글꼴 로딩과 무관하게 같은 모양이 나와야 한다.
  - `assets/kkachi/brand/kkachi-wordmark.svg`(`currentColor`)를 만든다.
  - 마크 단독 파일은 기존 favicon을 쓰되 필요하면 갱신한다.
  - OG 이미지도 새 워드마크로 다시 만든다.
- **쓰는 곳**: 상단 바, 푸터, 대시보드 사이드바, OG 이미지. 홈의 KKACHI 여섯 글자 아트는 브랜드 '그림'이므로 그대로 둔다.

## 3. 글꼴
- **Wanted Sans Variable**(OFL, wanteddev/wanted-sans)를 쓴다.
  - 사이트에서 쓰는 글자 기준으로 서브셋을 만들어 자체 호스팅한다. 라이선스 파일과 README를 함께 둔다.
  - 400–900 가변 굵기다. 숫자는 `font-variant-numeric: tabular-nums`가 필요한 곳(표, 수치, 시간)에 쓴다.
- **Fragment Mono**(OFL)는 코드, 헥스 덤프, 해시에만 쓴다. Latin 서브셋으로 자체 호스팅한다.
- 기존 `assets/fonts/pretendard`, `mono`, `portfolio-sans`는 포트폴리오 사이트 본체가 쓰므로 그대로 둔다. KKACHI 페이지만 새 글꼴로 바꾼다.

## 4. AI 티 제거 규칙 (모든 KKACHI 페이지)
- **빼는 것**
  - 번호와 엠대시가 붙은 eyebrow(`01 — Method / 작동 원리`).
  - 대문자에 자간을 넓힌 모노 마이크로 라벨.
  - 모든 라벨을 한/영 쌍으로 다는 것. 영어는 브랜드명과 코드 용어에만 남긴다.
  - 의미 없는 번호 매기기. 순서가 진짜인 곳(5단계, 1–3 안내)에만 쓴다.
  - "SAMPLE" 같은 영문 대문자 태그. 대신 한글 "샘플 데이터"를 작게, 그러나 분명하게 쓴다.
- **문장**: 짧고 구체적인 한국어로 쓴다. 홍보 문구 같은 과장, 수식어 나열, "~합니다." 연속 리듬을 피한다.
- **장식**: 의미 없는 장식, 그리드 배경, 글로우, 그라디언트를 쓰지 않는다. 자개만 브랜드 재질로 쓰고, 그것도 옻칠 위에서만 쓴다.

## 5. 통합 디자인 시스템 (`assets/kkachi/kk-system.css` + 문서)
- **테마**
  - 어두움(옻칠)이 기본이다. 밝음(mist)은 `[data-theme="light"]`이다.
  - 마케팅 페이지는 어두움으로 고정한다. 대시보드는 토글할 수 있다.
- **색 역할**
  - 바탕, 표면 1–3, 선(가는 선/강한 선), 글자 1–3, 포커스, 링크.
  - 브랜드 강조 = 자개(텍스처). 상태색 violet = 확인·발견.
- **심각도와 상태 색**
  - 심각도: Critical / High / Medium / Low / Info. 상태: 대기 / 실행 중 / 확인 / 기각 / 보류 / 실패.
  - 브랜드 팔레트(나전 jade #5D8D91, sage #98A197, lilac #928FA1, violet #96688D, heritage taupe #8F8279, rose-brown #877976)에서 끌어내되, 구분이 되도록 명도와 채도를 조정한다.
  - 대비는 UI 표지 3:1 이상, 글자 4.5:1 이상이다. 두 테마 모두에서 확인한다.
  - 색만으로 구분하지 않는다. 아이콘 모양이나 글자를 함께 쓴다.
- **글자 크기**
  - 마케팅(디스플레이): 큰 헤드라인부터 본문 17px까지.
  - UI(대시보드): 12/13/14/16/20/24px.
- **간격, 반경, 그림자**: 4px 기반 간격을 쓴다. 반경은 작게(0–4px) 두고, 그림자 대신 선과 표면 단계를 쓴다.
- **컴포넌트**
  - 버튼(주/보조/고스트/위험), 링크, 배지(심각도/상태), 표(정렬, 선택 행, 고정 머리), 탭, 세그먼트, 입력·검색·셀렉트, 체크박스.
  - 패널/카드, 사이드 내비, 상단 바, 토스트, 빈/로딩/오류 상태, 코드 블록, 그래프 노드/간선(콘솔 언어), 타임라인.
- **모션**
  - 마케팅은 지금의 느리고 차분한 루프를 유지한다.
  - 앱(대시보드)은 150–250ms의 기능적 전환만 쓴다.
  - 자개 셰이더는 '확인' 순간에만 쓰고, 금문 전환은 앱에서 쓰지 않는다.
  - `prefers-reduced-motion`을 지킨다.
- **문서**: `/kkachi/system/`에서 토큰과 컴포넌트를 실제 렌더로 보여 준다. 이 문서 §5와 같은 내용이다.
- **기존 파일 정리**
  - `kk-paper.css`(흰 페이지용)는 시스템으로 옮긴 뒤 삭제한다.
  - `kk.css`(홈)는 시스템 토큰을 쓰도록 정리한다.
  - `paper.js`의 공용 동작(스크롤 그리기, 상단 바)은 `kk-system.js`(또는 기존 이름 유지)로 정리한다.

## 6. `/kkachi/why/` 이야기 구조 (핵심만)
레퍼런스 패턴(문제 → 해법 → 증거 → 행동)을 따른다. 어두운 옻칠 바탕에 큰 타이포를 쓰고, 장면마다 하나의 메시지만 둔다.

1. **히어로**
   - 헤드라인: "많이 찾기보다, 확실히 찾습니다."(프로토타입 원칙 섹션 문장)
   - 한 줄 소개: "KKACHI(까치)는 코드와 바이너리를 읽고 호출 경로를 끝까지 따라가, 재현으로 입증된 취약점만 보고하는 자율 연구 에이전트입니다."
   - CTA: 대기자 명단.
2. **왜 필요한가(문제)**
   - 확인되지 않은 경고가 쌓이고, 사람의 검토 시간이 그 확인에 쓰인다. 빠진 것은 "실제로 닿는가, 재현되는가"라는 확인이다.
   - **새로 쓰는 문장이므로 정성적 주장만 쓴다.** 업계 통계나 수치를 지어내지 않는다.
3. **어떻게 작동하는가**
   - 읽기 → 가설 → 추적 → 재현 → 보고. 다섯 단계와 관문을 하나의 스크롤 장치로 보여 준다.
   - "앞 단계의 조건을 채우지 못하면 넘어가지 않고, 그 사실도 기록합니다."
4. **판단의 기록(대표 장면)**: "뚜껑을 열면, 판단의 기록이 보입니다."
   - 호출 그래프 추적이 재생된다. H2와 H3는 기각, H4는 보류, H1은 확인되며 F-01이 violet으로 확정된다.
   - 가설을 고르면 경로가 강조된다(현재 콘솔 인터랙션의 핵심).
5. **증거로 말하는 보고서**: "보고서는 증거로 말합니다." F-01 보고서의 요약, 근본 원인(207 → 212), 재현 명령, 수정 방향을 핵심만 발췌한다.
6. **원칙**: P1–P5를 한 줄씩 쓴다(허가된 대상, 격리 재현, 재현 없으면 발견 아님, 버린 가설 기록, 혼자 공개하지 않음).
7. **샘플 세션 수치**(샘플 데이터임을 분명히 표시): 함수 1,284개 · 가설 4개 · 기각 2 · 보류 1 · 재현 3/3 · 4분 12초.
8. **행동**: "반가운 소식만 가져오겠습니다." 대기자 명단 CTA와 연구 노트 링크를 둔다.

- 남길 사실은 프로토타입 문장에서 가져온다. 이번에 일부러 덜어내는 세부(전체 코드 205–214, 세션 기록 전체 타임라인, 보고서 06 검토 칸의 세부 등)는 구현 기록에 목록으로 남긴다.
- 정직성 규칙: 샘플 표시를 하고, 지어낸 사실과 수치를 쓰지 않는다.

## 7. 대시보드 샘플 `/kkachi/dashboard/`
- **앱 셸**
  - 왼쪽 사이드 내비: 워드마크, 개요, 세션, 발견, 대상, 설정. 샘플이므로 개요와 세션 상세만 동작한다.
  - 상단 바: 검색, 테마 토글, "샘플 데이터" 표시.
- **개요 화면**
  - 진행 중·완료 세션 수, 심각도별 발견 수, 최근 세션 표(세션, 대상, 단계, 경과, 상태).
  - 세션 7F2A를 고르면 상세가 열린다.
- **세션 상세**
  - 다섯 단계 진행(관문), 호출 그래프(콘솔 언어), 가설 H1–H4 목록(상태, 근거), F-01 발견 카드.
  - '확인' 순간에만 자개 강조를 쓴다.
  - 재현 3/3, 타임라인 스크러버를 둔다.
- **데이터**: 모든 데이터는 프로토타입의 샘플 세션 7F2A에서 가져온다. 추가 샘플 세션 몇 개는 "샘플"로 명시하고, 그럴듯한 가짜 고객명이나 실존 제품명을 쓰지 않는다.
- **품질**
  - 키보드로 완전히 조작할 수 있다(표 행 선택, 탭, 필터). 명확한 포커스를 둔다.
  - 1280 이상에서 밀도 있는 레이아웃, 768에서 접히는 내비, 390에서 단일 열.
  - 두 테마 모두 대비가 AA다.
