대기자 명단

Autonomous vulnerability research agent/자율 취약점 연구 에이전트

모든 경로를 따라가, 확인된 하나를 가져옵니다.

KKACHI(까치)는 코드와 바이너리를 읽고 가설을 세운 뒤, 호출 경로를 끝까지 따라갑니다. 재현으로 입증된 것만 발견으로 보고합니다.

copy_rows()의 행 길이 계산에서 정수 오버플로

sample-imgcodec 2.4 · src/rows.c:207 → 212 · CWE-190 → CWE-122 · 2026-09-26

01Summary요약

조작된 이미지 헤더의 width 값이 32비트 곱셈에서 넘쳐 행 버퍼가 실제보다 작게 할당되고, 이어지는 memcpy()가 힙 경계를 넘어 씁니다.

01첫 문단은 한 문장으로 끝납니다. 무엇이, 어디서, 왜.

02Impact영향

조작된 이미지 한 장으로 힙 버퍼 뒤쪽 메모리를 덮어쓸 수 있습니다. (추정 · 검토 필요)

02추정은 추정이라고 씁니다. 확인된 사실과 섞지 않습니다.

03Root cause근본 원인

src/rows.c:207 stride를 32비트로 계산 →src/rows.c:212 64비트로 다시 계산한 길이만큼 복사.

03모든 주장에는 코드 위치가 붙습니다.

04Reproduce재현

$ ./repro --seed 7f2a poc-f01.imgASan: heap-buffer-overflow · rows.c:212

격리 VM에서 3회 모두 같은 위치에서 중단됩니다.

04재현 절차는 복사해서 그대로 실행할 수 있어야 합니다.

05Fix수정 방향

  1. −삭제: u32 stride = h->width * h->bpp;
  2. +추가: if (h->width > MAX_W) return -1;
  3. +추가: size_t stride = (size_t)h->width * h->bpp;

05수정은 제안일 뿐입니다. 적용은 사람이 결정합니다.

04 — Principles/원칙

많이 찾기보다, 확실히 찾습니다.

  1. P1

    허가받은 대상만 봅니다.

    소유자나 권한자가 승인한 범위 안에서만 분석하고 실행합니다. 범위 밖의 주소, 저장소, 바이너리에는 손대지 않습니다.

  2. P2

    격리된 곳에서만 재현합니다.

    재현은 매번 새로 만든 일회용 샌드박스 안에서 실행하고, 실행 기록은 보고서에 첨부합니다.

  3. P3

    재현되지 않으면 발견이 아닙니다.

    추측은 가설로 남기고, 보고서에는 쓰지 않습니다.

  4. P4

    버린 가설도 기록합니다.

    무엇을 왜 버렸는지가 다음 연구를 빠르게 만듭니다. 틀린 길을 아는 것도 증거입니다.

  5. P5

    혼자 공개하지 않습니다.

    보고서는 사람의 검토를 거친 뒤에만 밖으로 나갑니다. 제보 채널과 공개 시점은 사람이 정하고, 조율된 공개(coordinated disclosure)를 기본으로 합니다.
