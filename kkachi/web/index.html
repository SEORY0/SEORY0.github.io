KKACHI Web — live web application testing

Your live app, tested the way an attacker would.

KKACHI Web explores running web applications and APIs inside the scope you approve, and proves each issue with a request sequence you can replay yourself.

Ask for Early access ↗ or see how it works ↓

How it works

  1. 01

    Map

    Routes, forms, APIs, and roles, explored with the test accounts you provide.

  2. 02

    Suspect

    Access control, injection, and business-logic paths become hypotheses.

  3. 03

    Probe

    Non-destructive requests test each one. Nothing is deleted, sent, or bought.

  4. 04

    Prove

    A finding is a request sequence that triggers the issue three times in a row.

  5. 05

    Report

    Impact, the exact requests, and a fix direction, waiting for a person to sign off.

Guardrails

Approved scope only

Hosts and paths come from an allowlist you set. Everything else is refused.

Rate limits

It stays under the request rate you choose, so production traffic is never crowded out.

No destructive actions

It reads and probes. It never deletes data, completes payments, or messages real users.

Human sign-off

Nothing is disclosed or retested in production until a person approves it.

Pairs with KKACHI Code

When source is available, a finding in the running app is traced back to the line that caused it.
