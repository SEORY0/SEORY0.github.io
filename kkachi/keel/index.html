Keel — agent harness

The harness under every agent.

Keel is the loop, memory, tools, and sandboxes our agents run in. Sessions last for days, borrow real machines only when a task needs one, and leave a record you can replay step by step.

Ask for Early access ↗ or read how Keel works ↓

Why a harness

A frontier model is not an agent. Without a harness, long work dies with its process, idle sessions keep burning compute, and nobody can say afterward why the agent did what it did.

What Keel does

Durable sessions

A session survives restarts and deploys. It resumes where it stopped, with its context intact.

Borrowed compute

Shells, builds, and fuzzers run on machines Keel attaches only for the task, then releases.

Full replay

Every model call, tool call, and decision is recorded in order. Any session can be replayed and audited.

Model-agnostic

Keel routes each step to the model that fits it, and swaps models without rewriting the agent.

Built to carry KKACHI

KKACHI Code and KKACHI Web both run on Keel. Every reproduction, every rejected hypothesis, and every report draft is a Keel session you can open and replay.
